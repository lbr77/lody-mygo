## Links

lody-ios registers the `lody` URL scheme (`apps/ios/App/Info.plist`). Lody Native declares it in `mygo.json` and opens `lody://session/<id>?workspace=<id>` and `lody://chat/new?machine=…&project=…&workspaceSlug=…` as Lody's desktop app does (`internal/app/deeplink.go`); Settings › About sets it as the default app for the scheme.

## Out of scope

- The iOS simulator stream (`SimulatorStream`), which this desktop client leaves out by choice.
- E2EE workspaces: neither lody-ios nor Lody's web client opens encrypted content (Lody's `@lody/e2ee-core` README: production E2EE composition is not enabled and no browser or native implementation is); Lody Native, like them, asks `e2eeWorkspaces:describe` and holds an encrypted workspace's content back with an explanation, except in local-only mode, where the machine's daemon serves it.
- lody-ios's second URL scheme, `app.innei.lody`, which names that app's own bundle. Of the `lody://` routes Lody's desktop app takes beyond the two above, the cloud callbacks (`auth/callback`, `invite/open`, `github-install`, `checkout-return`, `machine/connect`) aren't taken, since Lody Native signs in with the device flow and its GitHub and billing pages return to lody.ai, and neither is `provider/import`.
